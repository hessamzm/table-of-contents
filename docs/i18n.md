# Internationalization workflow

## Source of truth

Keep the editable translations in the locale PO files:

- `languages/table-of-contents-fa_IR.po`
- `languages/table-of-contents-ar_AR.po`

The POT file is the extracted source template:

- `languages/table-of-contents.pot`

Do not hand-edit generated `.mo` or `.l10n.php` files.

## Update the template

From the plugin root:

```bash
wp i18n make-pot . languages/table-of-contents.pot --slug=table-of-contents --domain=table-of-contents
```

Review the extracted strings, then update existing PO files:

```bash
wp i18n update-po languages/table-of-contents.pot languages/table-of-contents-fa_IR.po
wp i18n update-po languages/table-of-contents.pot languages/table-of-contents-ar_AR.po
```

## Build runtime translation files

Generate MO files:

```bash
wp i18n make-mo languages/table-of-contents-fa_IR.po languages/table-of-contents-fa_IR.mo
wp i18n make-mo languages/table-of-contents-ar_AR.po languages/table-of-contents-ar_AR.mo
```

Generate PHP translation files for WordPress 6.5+:

```bash
wp i18n make-php languages/table-of-contents-fa_IR.po languages/
wp i18n make-php languages/table-of-contents-ar_AR.po languages/
```

The generated files should be committed together:

```text
languages/
├── table-of-contents.pot
├── table-of-contents-fa_IR.po
├── table-of-contents-fa_IR.mo
├── table-of-contents-fa_IR.l10n.php
├── table-of-contents-ar_AR.po
├── table-of-contents-ar_AR.mo
└── table-of-contents-ar_AR.l10n.php
```

## Runtime behavior

The plugin registers its `languages/` directory with `load_plugin_textdomain()`. WordPress handles translation loading and, on modern WordPress versions, prefers the PHP translation format when available.

The plugin does not manually load a `.l10n.php` file through `load_textdomain()`; that API expects the MO path and WordPress resolves the preferred translation format itself.

## Translation QA

Before a release:

1. Confirm every non-empty POT string has a translation in each shipped locale.
2. Regenerate both MO and PHP translation files from the PO sources.
3. Run the PHPUnit suite.
4. Test the Settings page with a user whose dashboard locale is `fa_IR`.
5. Test the same page with `ar_AR`.
6. Clear PHP opcode/object caches if the environment previously loaded an older translation file.
7. Verify that no English admin labels remain where a shipped translation exists.
